# 온보딩 설계 — 사용자는 어떻게 카트리지를 채우는가

> 🇬🇧 English: [onboarding-design.en.md](onboarding-design.en.md)

> Phase 2(install.sh)·Phase 3(web-UI)의 UX 설계 문서. 2026-07-21 확정.
> 관련: [DEVELOPMENT.md](../DEVELOPMENT.md) 로드맵 · [cartridges/_template/](../cartridges/_template/)

## 설계 원칙

**사용자에게 내부 포맷(YAML·intent 프롬프트)을 절대 직접 요구하지 않는다.
원재료 → 내부 포맷 변환은 방금 설치한 그 LLM이 한다.**

모델 다운로드가 끝난 순간 콘솔에는 일 시킬 수 있는 LLM이 로컬에 존재한다.
이것을 온보딩 도구로 재사용한다 — **콘솔이 자기 자신을 셋업하는 자기부트스트랩.**

## 전체 온보딩 흐름

```mermaid
flowchart LR
    I["install.sh"] --> S1["1️⃣ HW 감지<br/>모델 선택·다운로드"]
    S1 --> S2["2️⃣ 캐릭터 생성 위저드<br/>5문답 → 프롬프트 초안"]
    S2 --> S3["3️⃣ 지식 채우기<br/>파일 던지기 → 변환 → 검수"]
    S3 --> S4["4️⃣ 카트리지 저장<br/>cartridges/my-domain/ 생성"]
    S4 --> GO["🚀 기동"]
    style S1 fill:#dcfce7,stroke:#22c55e
    style GO fill:#dcfce7,stroke:#22c55e
```

[4]가 핵심: 위저드 결과물은 `cartridge.yaml + prompts/ + knowledge/` 디렉토리로 저장된다.
**사용자가 만든 것이 곧 배포·공유 가능한 카트리지** — 위저드는 카트리지 에디터다.

## 슬롯 A: RAG 지식 — 입력 경로 3개 + 변환 모드 2개

### 입력 경로 (쉬운 것부터)

| 경로 | 대상 | 동작 |
|---|---|---|
| **① 파일 던지기** | 대부분 | PDF/MD/DOCX/TXT 드래그&드롭 → 자동 변환·임베딩 |
| **② 폼 입력** | Q&A를 직접 다듬을 사람 | web-UI "질문/답변" 카드 → 뒤에서 qna YAML 생성 |
| **③ YAML 직접** | 파워유저·카트리지 제작자 | `_template` 규격 작성 → bulk 업로드 (기존 경로) |

### 변환 모드 (①의 내부 동작 — 둘 다 지원)

| 모드 | 동작 | 노력 | 품질 |
|---|---|:--:|:--:|
| **문서 모드 (청크)** | 문서를 조각내 그대로 임베딩 | 0 | 보통 |
| **큐레이션 모드 (LLM 변환)** | 로컬 LLM이 문서를 읽고 qna YAML 초안 생성("나올 법한 질문 N개 + 답변 + aliases") → 사용자 검수 → 적재 | 검수만 | 높음 |

- 원본(secops)의 강점이 바로 큐레이션 품질(question/answer/aliases 구조)이었다.
  이를 자동화하는 큐레이션 모드가 이 제품의 차별점.
- ⚠️ **엔진 수정 필요 지점**: 현재 RAG payload는 qna/action 단위만 받는다.
  문서 모드용 **청크 타입 payload 추가**가 유일한 RAG 코어 수정.

## 슬롯 B: 프롬프트 — "캐릭터 생성" 위저드

게임 콘솔 은유 그대로: 새 게임 시작 → 캐릭터 생성 화면.
사용자는 프롬프트를 "작성"하지 않고 **질문에 답하며 캐릭터를 빚는다**:

```
1. 이 에이전트는 무엇을 하나요?      → 역할 정의 (한 문장)
2. 누가 쓰나요?                      → 청자·전문성 수준
3. 어떤 말투로?                      → 존댓말/간결/상세 (선택지 클릭)
4. 반드시 지킬 규칙은?               → 금지사항·출력 형식
5. [고급] 작업 생성이 필요한가요?    → yes → ACTION intent 활성화
```

- 답변 → **로컬 LLM이 시스템 프롬프트 초안 생성**(메타 프롬프팅)
  → 미리보기에서 **테스트 대화** → 수정 → 저장(`config [prompts]` 연결)
- **intent는 기본 1개(QNA)로 시작.** 대부분의 목표는 "내 문서에 답하는 챗봇" —
  intent 분류는 과하다. 5번에서 yes일 때만 ACTION/PLAN이 열리는 **점진 공개**.
- **갤러리 병행** (백지 공포 제거): `문서 Q&A` / `고객 지원` / `코딩 도우미` /
  `secops(레퍼런스)` 프리셋 카트리지에서 시작해 고쳐 쓰는 경로.

## 미결정 (구현 시점에 판단)

- 청크 전략: 고정 길이 vs 구조 인식(마크다운 헤더 단위) — 실측 비교 후 결정
- 큐레이션 모드의 질문 생성 개수 기본값 (문서 길이 비례?)
- 위저드 다국어: 첫 릴리스는 한국어/영어 2종 메타 프롬프트
- PDF 파싱 라이브러리 선정 (표·이미지 처리 수준)
